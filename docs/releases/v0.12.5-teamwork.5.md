# v0.12.5+teamwork.5

[English backup](v0.12.5-teamwork.5_en.md)

`v0.12.5+teamwork.5` 继续绑定上游 Spec Kit `v0.12.5`，Team 扩展升级为
`0.10.0`。本版本把需求确认、架构设计、项目资料加载、质量门禁和发布收尾连接成
一条兼容旧项目的团队工作流。

## 主要变化

- `speckit.team.specify` 在离开 Specify 阶段前展示具体 Feature Record、简化版
  User Story 和 Verification，获得人工确认后再回填；旧项目未配置时保持 advisory。
- 明确 L0、L1、Feature、L2、Plan 和 Task 的不同视角，并新增仓库级共享契约模板
  与从个人候选提升为团队权威契约的路径。
- 新增 `speckit.team.complete`，只验证已经存在的合并与发布证据并回填 Feature
  Record，不替人执行合并、发布、部署或关闭上层需求。
- 可选的项目资料清单可以按角色、阶段、模块和顺序加载；没有清单时不阻塞旧项目。
- 可配置质量门禁支持静态检查、命令检查和 Model-as-Judge；模型判断失败默认
  `NO-GO`，只有经过具名人工评估后才能降为 `GO-WITH-RISK`。

## 兼容性

- 历史项目没有 `behavior_confirmation` 配置时采用 advisory，不会突然阻断进行中的
  Feature。
- 历史 `done` 记录不强制补齐新增的 `release.evidence` 和 `completion.*`；只要开始
  填写新字段，就必须形成完整证据包。
- Git 发布证据默认 best-effort；只有显式启用严格模式时才要求全部本地可解析。

## 发布与安装

在发行 PR 的合并提交创建 `v0.12.5+teamwork.5` tag。tag 创建后使用：

```bash
uv tool install specify-cli --force \
  --from git+https://github.com/EuphoriaYan/spec-kit.git@v0.12.5+teamwork.5
specify init . --integration <codex|claude|cursor-agent|trae>
```

需要回滚时重新安装 `v0.12.5+teamwork.4`，再检查项目生成文件差异。
