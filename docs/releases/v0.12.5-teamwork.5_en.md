# v0.12.5+teamwork.5

[中文主文档](v0.12.5-teamwork.5.md)

`v0.12.5+teamwork.5` remains based on upstream Spec Kit `v0.12.5` and updates
the Team extension to `0.10.0`. It connects behavior confirmation,
architecture design, project-context routing, quality gates, and completion
backfill while preserving compatibility for existing projects.

## Highlights

- `speckit.team.specify` presents the exact Feature Record, simplified User
  Stories, and Verification evidence before human confirmation and writeback;
- L0, L1, Feature, L2, Plan, and Tasks are distinct viewpoints, with a
  repository-owned shared-contract promotion path;
- `speckit.team.complete` validates existing merge and release evidence and
  backfills one Feature Record without merging, releasing, deploying, or
  closing the parent Requirement;
- an optional context manifest routes project documents by role, phase,
  module, and order without blocking projects that do not have a manifest;
- versioned static, command, and Model-as-Judge rules produce auditable
  `GO`, `GO-WITH-RISK`, or `NO-GO` evidence.

## Compatibility

- Existing projects that omit behavior-confirmation policy remain advisory.
- Historical `done` records are exempt from the new completion bundle until
  any new completion field is populated.
- Git release evidence defaults to best-effort and no longer treats local
  `HEAD` ancestry as release authority.

## Release and install

Create `v0.12.5+teamwork.5` on the release PR merge commit. Once the tag
exists, install with:

```bash
uv tool install specify-cli --force \
  --from git+https://github.com/EuphoriaYan/spec-kit.git@v0.12.5+teamwork.5
specify init . --integration <codex|claude|cursor-agent|trae>
```

To roll back, reinstall `v0.12.5+teamwork.4` and inspect the refreshed project
files before committing them.
